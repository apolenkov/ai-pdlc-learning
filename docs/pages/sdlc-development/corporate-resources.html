Jira

Адрес — в корпоративной инструкции
Как войти
Откройте Jira, войдите с корпоративной учётной записью и выберите проект вашей команды.
Кто выдаёт доступ
администраторы проекта вашей команды; их список выдаёт организатор курса.
Если не получилось
Если Jira не открывается, проверьте рабочую сеть и запросите сетевой доступ. Если Jira открывается, но проект вашей команды недоступен, обратитесь к любому администратору проекта.
Проверка готовности
Проект вашей команды открывается, а разрешённые вашей ролью действия доступны.

Корпоративный GitLab

Как войти
Откройте GitLab и выберите вход через корпоративный SAML Single Sign-On. Если система не открывается, проверьте подключение к рабочей сети и запросите доступ к рабочей сети; вход выполняется кнопкой SAML.
Кто выдаёт доступ
Корпоративная система Git: SAML-вход, доступ к группе вашей команды и право создать fork учебного репозитория в личном namespace. Write в центральном репозитории не нужен; main защищена, работайте в личных ветках course/<login>/....
Если не получилось
Если fork не создаётся, проверьте рабочую сеть и разрешённый namespace. Если push отклонён, выполните git remote get-url origin: адрес должен вести в ваш namespace; затем проверьте имя личной ветки. Если корпоративная политика запрещает fork, остановитесь и сообщите организатору.
Проверка готовности
Личная ветка course/<login>/... отправлена в origin и не отстаёт от него, а MR создан внутри fork; как это проверить, описано в блоке «Токен и Git CLI: авторизация и диагностика». Получите одобрение владельца продукта и комментарии аналитика и техлида; архитектора подключите по признакам или при споре. Затем можно объединить MR с личной base-веткой fork. Модель одобрение не даёт.

Основной путь: fork в GitLab → клонирование и работа в VS Code

Создайте личный fork учебного репозитория из группы вашей команды и откройте его в VS Code: сами действия коротко повторяет карта Git-процесса, подробности и пояснения — в подготовке «Markdown, Git, GitLab». Каждому действию соответствует место на карте: Fork и Clone → Create Branch → правка и diff → Stage и Commit → Push → MR → review → merge.

Токен и Git CLI: авторизация и диагностика (продвинутый уровень)

Терминальный Git и запрос пароля из VS Code при работе по HTTPS используют личный токен доступа, а не пароль домена.

  1. Войдите в GitLab через SAML Single Sign-On.
  2. Создайте токен: аватар → Edit profile → Access tokens → Add new token; имя course-git, срок действия — короткий, scopes read_repository и write_repository; скопируйте токен сразу — он показывается один раз.
  3. При первом clone или push: Username — корпоративный логин GitLab, Password — токен, а не пароль домена.
  4. Проверьте доступ к репозиторию: git ls-remote https://<адрес GitLab>/<логин>/<репозиторий>.git. Увидите список ссылок репозитория — ветки и теги; если вместо него появилась ошибка доступа, проверьте токен и вход через SAML.
  5. Проверьте менеджер учётных данных: git config --global --get credential.helper. Увидите имя помощника, например manager на Windows или osxkeychain на macOS; пустой ответ значит, что Git будет спрашивать логин и токен при каждом действии.
  6. Обновите сведения об удалённых ветках: git fetch. Команда завершится без ошибок и покажет новые ветки, если они появились.
  7. Проверьте свою ветку: git status --short --branch. В строке с вашей веткой видно, на сколько она ушла вперёд или отстала от origin.
  8. Токен не вставляйте в чат, файлы, URL и скриншоты; при утечке отзовите его в Access tokens и выпустите новый.

OpenSpec CLI: установка из npm

Единый рецепт курса для всех ОС — npm-вариант официальной инструкции OpenSpec. Официальная инструкция ставит один бинарный файл без Node.js; npm она предлагает при Node.js 20.19+, курс закрепляет npm-версию. Инструменты для вашего шага — в таблице «Что нужно по шагам». На Windows и в VDI глобальную установку выполняйте только согласованным пакетом и выданными правами после заявки на установку ПО; sudo и обходные схемы не применяйте.

  1. Для курса проверьте Node.js версии 22 или новее: node --version. Если версия ниже, установите Node.js LTS с официальной страницы.
  2. Установите CLI закреплённой курсом версии: npm install -g @fission-ai/openspec@1.12.0. Официальная инструкция предлагает @latest; ориентир версии курса — pin @fission-ai/openspec@1.12.0 в package-lock.json учебных репозиториев, обновляйте глобальный CLI только вместе с этим pin.
  3. Проверьте установку: openspec --version должна вывести 1.12.0.
  4. Когда гайд предпишет инициализацию, выполните openspec init в корне вашего существующего проекта — не заранее и не в произвольной папке.

Kilo Code в VS Code: настройка работы с моделью

Настройте подключение один раз. На шагах 1–2 вам нужны Git и VS Code. Если выбираете блоки «С моделью» внутри шагов 1–3, используйте Kilo Code с корпоративным провайдером модели. Шаг 5 выполняется только с моделью. VS Code + Kilo Code — основной инструмент работы с моделью в курсе. Node.js 22+ и OpenSpec CLI нужны начиная с шага 3. Project skills для Kilo приходят вместе с базой учебного блока: шаги 1, 2 и отдельный эталон шага 3 содержат три навыка планирования в .kilo/skills; на шаге 3 команда openspec init --tools none создаёт только корень OpenSpec и не создаёт и не меняет навыки. Выданная база шага 5 содержит skill подготовки в .agents/skills/. Выберите один маршрут работы с моделью. На доменной Windows и в VDI работайте в Kilo Code. Только на личном компьютере с macOS или Linux можно выбрать OpenCode. Результат модели проверяете вы, а одобрение дают люди.

Для сопровождающих · что подтвердила локальная проверка

Зафиксированная локальная проверка — одна конфигурация, а не глобальная сертификация: 23.09.2026 расширение kilocode.kilo-code в VS Code с корпоративным провайдером и корпоративной моделью загрузило project skill setup-analysis-workspace из .agents/skills/ в одноразовом несекретном клоне требований для шага 5 и полностью его выполнило: Store doctor без замечаний, обе подготовки окружения завершились успешно. Наблюдаемая версия расширения — 7.7.7; эта версия не обязательна, ставьте разрешённую актуальную. Локальная проверка — свидетельство сопровождающих, а не указание ученику выполнять дополнительную инициализацию. До отдельного решения ИБ работайте только в несекретном учебном проекте.

Установите и проверьте Kilo Code перед первым блоком «С моделью» в шагах 1–3 или перед началом шага 5:

  1. На Windows или VDI сначала оформите заявку на установку ПО. Затем откройте Extensions в VS Code, найдите расширение по точному идентификатору kilocode.kilo-code и установите его разрешённым способом. Сверяйтесь с официальными инструкциями по установке и работе в VS Code.
  2. В Kilo откройте Settings → Providers и добавьте корпоративный провайдер с идентификатором из корпоративной инструкции. Адрес подключения получите только из корпоративной инструкции или у администратора: не публикуйте и не переносите его из чужой конфигурации. Порядок полей описан в Custom Models.
  3. Выберите модель, указанную в корпоративной инструкции, по её полному идентификатору. В проверенном файле конфигурации поле API-ключа отсутствует — официальная документация допускает провайдера без ключа; не добавляйте его без отдельного требования администратора. Варианты авторизации сверяйте с официальной инструкцией Kilo.
  4. Откройте несекретный учебный проект и отправьте в Kilo проверочный запрос: Ответь ровно: подключение работает. Проверка пройдена, когда выбран корпоративный провайдер и корпоративная модель отвечает «подключение работает». Не вставляйте в чат токены, пароли, ключи или содержимое закрытых конфигураций.
  5. Задачи курса начинайте кнопкой «Новая сессия» над полем ввода Kilo. Кнопку «Новое Worktree» рядом не нажимайте: она создаёт копию репозитория в .kilo/worktrees/, и правки не попадут в вашу учебную папку. Если нажали, закройте вкладку Agent Manager и начните снова через «Новая сессия».

Лимиты модели — это нормально. У корпоративной модели и сервиса есть пределы на запрос, контекст и объём ответа, поэтому Kilo Code иногда останавливается без результата — это не обязательно ваша ошибка. При ограничении частоты запросов повторите попытку через время, указанное в самом сообщении. Если ответ оборвался, проверьте уже сохранённые файлы и попросите в той же задаче продолжить оставшуюся часть, не дублируя сделанное; при повторном обрыве сократите запрос. Если Kilo показывает The model hit its output limit while reasoning and produced no actionable output, модель израсходовала предел ответа на рассуждение: напишите в той же задаче «продолжай». Незавершённый отчёт не считается успешной проверкой или ревью; автоматическое восстановление не гарантируется.

OpenCode · необязательная продвинутая альтернатива Kilo · только личный компьютер

Для блоков «С моделью» в шагах 1–3 и для шага 5 вы можете выбрать OpenCode вместо Kilo на личном компьютере. На шаге 3 он работает с project skills, в шаге 5 — с project skills и Store. В сквозном маршруте инициализацию шага 3 выполняйте по отдельному шагу; отдельные эталоны уже содержат нужные skills. Запускайте OpenCode во встроенном терминале VS Code командой opencode из корня проекта.

1. Установка и провайдер

На доменной Windows и в VDI используйте Kilo Code в VS Code. Только на личном компьютере с macOS или Linux установите OpenCode по официальной инструкции. Из корня проекта запустите opencode либо opencode web.

Возьмите параметры только из корпоративной инструкции. В OpenCode Web откройте Настройки → Провайдеры, добавьте пользовательского провайдера с идентификатором из корпоративной инструкции и заполните поля по выданным значениям. Адрес подключения на этой странице намеренно не публикуется. Сверяйтесь с официальной инструкцией провайдера.

Ключ, если его потребует администратор, вводите только в защищённое поле настроек; не переносите его в сообщение, команду, Git или снимок экрана.

2. Корпоративная модель

Откройте модели корпоративного провайдера и выберите полный идентификатор модели из корпоративной инструкции. Не сокращайте имя и не выбирайте публичную модель по умолчанию. Точный порядок выбора описан в официальной инструкции по моделям.

В настройках моделей OpenCode Web модели корпоративного провайдера собраны в отдельную группу с его именем. Выбранная модель отмечена в ней полным идентификатором: сверьте его с корпоративной инструкцией символ в символ.

3. Проверочный запрос

В несекретном учебном проекте отправьте: Ответь ровно: подключение работает. Продолжайте курс только после ответа «подключение работает» от выбранной корпоративной модели. При ошибке передайте поддержке её текст без токенов, ключей и конфигурации.

Другие варианты: Cline и Continue на обследованной машине не установлены и в учебном маршруте не проверены. Ссылки даны только для сравнения; поддержка и совместимость не заявляются.

Windows / VDI

Обязательно: на Windows и в VDI любую установку из этой карточки выполняйте только после заявки и согласования ИБ/ИТ.

  1. Git for Windows: откройте официальную страницу, установите Git и запускайте Bash-команды гайда в Git Bash.
  2. Node.js: установите LTS с официальной страницы; npm входит в установку. Для курса используйте Node.js 22+.
  3. OpenSpec: откройте официальную инструкцию и установите CLI разрешённым способом; инициализацию выполняйте только в том гайде, где она указана.
  4. VS Code: откройте страницу загрузки VS Code, установите редактор и откройте рабочую папку. Для работы с моделью поставьте расширение kilocode.kilo-code; см. настройку Kilo Code.
  5. onUI (только для авторов и проверяющих): откройте магазин Chrome или магазин Edge, добавьте расширение, отметьте элемент, скопируйте отчёт и отправьте его по согласованному каналу.

Команды: Bash-синтаксис гайда запускайте в Git Bash. В PowerShell используйте npm.cmd ci и npm.cmd run check; не переписывайте Bash-команды наугад. Зависимости, Remote-SSH, ограничения и проверка готовности
Что ставит npm ci
В учебных репозиториях шагов 3–5 npm ci читает package-lock.json и ставит локальные dev-зависимости: @fission-ai/openspec@1.12.0, tsx, typescript, @types/node; в code checkout также vite. Команды npm exec openspec и npm exec tsx используют эти локальные версии. В сквозном маршруте шага 3 отдельно нужен native OpenSpec CLI в PATH для bare-команд openspec. Playwright в этих учебных manifest не входит, а onUI устанавливается как расширение браузера, не через npm. tsx, TypeScript и Vite отдельно не запрашивайте: это локальные зависимости проекта из package-lock.json. make в маршруте не используется. Если npm предлагает скачать пакет вне lock-файла, остановитесь и согласуйте реестр или пакет с ИБ.
Remote-SSH (если нужен)
Для подключения к VM с Windows, macOS или Linux нужны VS Code с расширением Remote-SSH, клиент OpenSSH и корпоративная сеть; проверьте ssh -V. На VM остаются Node.js/runtime, Docker, базы данных и инструмент работы с моделью. JetBrains Toolbox и DBeaver устанавливайте только если этого требует стек проекта; на Windows/VDI — после заявки и согласования ИБ/ИТ.
Что не ставится
Jira, GitLab, Confluence и корпоративный ИИ — это веб-системы: им нужны рабочая сеть, SSO и выданные права. Установка локального CLI сама по себе не выдаёт доступ к проекту, модели или репозиторию.
Кто выдаёт доступ
Для корпоративной машины или VDI заявку согласует ИБ; установочный пакет и права выдаёт владелец рабочего места или корпоративная поддержка.
Если не получилось
Если загрузка, магазин расширений или Git Bash заблокированы, передайте корпоративной поддержке название инструмента и прямую ссылку из этой карточки. Для Windows/VDI оформите заявку на установку ПО.

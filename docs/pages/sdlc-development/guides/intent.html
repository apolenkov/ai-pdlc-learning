этап 1 PDLC

Намерение и план

Сначала коротко записываем проблему, ожидаемый эффект, что не трогаем и из каких изменений состоит результат. Потом запись проверяют, одобряет её владелец продукта.

intent.md — файл записи намерения: один короткий документ на один запрос. Он лежит в Git рядом с кодом: Git — система хранения версий, она помнит, кто и когда менял документ и какую версию приняли.

PDLC — жизненный цикл продукта от замысла до наблюдения. Этап намерения — первый: принятая запись намерения с ревизией становится входом этапа «Анализ требований».

Проблема → цель

Сейчас

  • Запрос приходит письмом с готовым решением: «сделайте кнопку „Очистить“».
  • Эффект не назван числом, границы неполные.
  • Через месяц начинается спор «мы это не просили».

Цель

  • intent.md в Git: проблема словами пользователя.
  • Сейчас 42 обращения в неделю. К марту — не больше 25. Оба числа учебные.
  • Границы и план изменений названы, одобрение одно — владельца продукта.

Подготовка

Обязательно

  • Зачем меняем процесс — почему документы живут в Git и принимаются запросами на слияние.
  • Markdown, Git и GitLab — Markdown — формат текста с разметкой, Git хранит версии, GitLab ведёт ветки и запросы на слияние.

Рекомендуется

  • SDD и OpenSpec — SDD (разработка от спецификации) ведёт от проверяемого документа к коду, OpenSpec раскладывает требования отдельными изменениями.
  • Мета-репозиторий — общая папка продукта: границы продукта, словарь терминов и правила работы.

Карта показывает подготовку по порядку; эти две части можно пропустить и перейти к шагу 1 после «Markdown, Git и GitLab».

Как достичь уровня

Курс доводит команду до уровня 3 «В репозитории с одобрением». Признаки всех уровней на карте зрелости намерения.

Словарь ролей

Владелец продукта
пишет и одобряет запись намерения (эффект и границы), а в курсе анализа одобряет спецификацию (проверяемые требования).

Передача в анализ

Для принятия нужны комментарии техлида (реализуемость плана) и аналитика (хватает ли записи для анализа) на последней версии и одно одобрение владельца продукта. Одобрение относится к ревизии: после правок смысла его нужно получить заново.

Аналитик записывает передачу в комментарии к одобренному MR: кто принял, ссылку на MR, полный хеш коммита (SHA), путь к intent.md и идентификатор выбранной строки плана (change-N). Каждое изменение анализа ссылается на свой пункт плана и эту ревизию; принятый документ не меняют. Порядок и образец записи передачи.

Курс анализа — самостоятельный учебный пример по тому же обращению калькулятора, не продолжение вашей ветки. В его подготовке вы составите отдельный замысел по короткому шаблону; переданный change-N при этом не выполняется.

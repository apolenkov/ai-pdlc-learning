# Проверки качества запускаются автоматически и краснят job

- Статус: принято, внедряется в TASK-524
- Контекст: оценка TASK-515, рубрики C2, C3, G2, G3, S2, T3, T4, A3

## Изменение от 20.10.2026 (TASK-615, CI-FLEET); 27.10.2026 — build-site убран (TASK-727)

По решению владельца проверки перенесены из CI в штатный Lefthook `pre-push`:
сканирование секретов в истории, дереве и сборке, audit, lint, boundaries, форматирование,
типы, OpenSpec, тесты с покрытием и четыре мутационных гейта. Их пороги сохранены.
Проверка Linux-shim запускается локально только на Linux; на других ОС выводится NOT VERIFIED.
CI выполняет только ручную выкладку `pages` на `img-build`; workflow не менялся: конвейер создаётся
для MR и push в default-ветку без дублирующего branch pipeline, выкладки Pages сериализованы через
`resource_group`. По решению владельца от 27.10.2026 (TASK-727) из CI убрали все сборки: `build-site`
удалён, сайт собирают локально `npm run build:site`, та же сборка входит в `pre-push`. В CI остаётся
только выкладка `pages` — она запускается вручную, когда подключится DevOps.
Ниже сохранено исходное решение; его требования о месте запуска проверок заменены этим изменением.

## Контекст

До TASK-524 в CI проверки запускались вручную на merge request, lint и форматирование отсутствовали,
уязвимости зависимостей не проверялись, а тесты не имели независимого контроля силы.

## Решение

- `source-checks` запускается автоматически на каждом merge request и на главной ветке и включает gitleaks, `npm audit --audit-level=high`,
  ESLint, Prettier, типы, строгую проверку OpenSpec, тесты и сборку сайта.
- `audit:high` падает и на найденной уязвимости, и на недоступном реестре (fail-closed); поведение проверено на loopback-реестре в `scripts/audit-gate.test.ts`.
- Мутационный гейт Stryker на калькуляторе (`mutation:credit`) блокирует merge request при счёте ниже 70.
- `test:coverage` (c8 с `--all`) считает незагруженные production-файлы покрытыми на 0% и падает ниже порогов из `.c8rc.json`; тестовые опоры (`*-test-support.ts`, `learner-guide-contract*.ts`) и файлы только с типами в реестр не входят. Пороги выставлены чуть ниже замера и поднимаются вместе с покрытием.
- `npm run boundaries` (dependency-cruiser) падает на циклах, импортах рантайма из `scripts` в браузерный код, импортах тестов из production и неразрешимых импортах.
- Локальный `pre-commit` запускает lint и проверку форматирования перед typecheck; хуки не обходятся.
- Обновление зависимостей делают агенты; запуск Renovate по расписанию с токеном CI не вводится (решение владельца), файл `renovate.json` остаётся описанием политики версий.

## Последствия

- В CI на root-раннере шесть тестов с ограничением прав (`chmod`) пропускаются (`skipped 6`): root игнорирует права доступа. Локально они проходят.
- Проверка занимает около 1,5–2 минут; расширение мутационного гейта на другие модули — отдельное решение.
- Настройка GitLab «pipeline должен быть зелёным» выключена по решению владельца: красный job не запрещает слияние сам, его соблюдает дисциплина слияния. Включение настройки сделало бы гейты запрещающими на уровне GitLab.
- Пороги покрытия измерены локально; на root-раннере пропуск шести тестов может снизить показатель, запас — несколько пунктов.

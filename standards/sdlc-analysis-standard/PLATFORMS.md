# Платформы и команды

Основной пример стандарта проверяется на macOS. Команды ниже не требуют
секретов и не подключаются к Jira, Confluence или корпоративной модели.

Сначала из корня метарепозитория установите зависимости по корневому
`package-lock.json`:

```sh
npm ci
```

Затем перейдите в `standards/sdlc-analysis-standard`. Не запускайте `npm ci` в
каталоге стандарта: этот внутренний эталон использует зависимости корневого
метарепозитория.

## macOS

```sh
make bootstrap
make doctor
make validate
make test
```

Если `make` не установлен, используйте эквивалентные команды:

```sh
npm run bootstrap
npm run doctor
npm run validate
npm test
```

## Windows

> **Важно для ИБ.** Node.js устанавливает npm вместе с runtime. На Windows и в VDI установку Git, Node.js, OpenSpec, OpenCode, VS Code, WSL и расширений начинайте только после заявки и согласования ИБ/ИТ. На личных macOS и Linux используйте официальные инструкции; `npm ci` запускайте только из разрешённого репозитория и по его `package-lock.json`.

В PowerShell из корня метарепозитория выполните `npm.cmd ci`. Затем перейдите
в каталог стандарта и при необходимости используйте `npm.cmd` вместо `npm`:

```powershell
npm.cmd run bootstrap
npm.cmd run doctor
npm.cmd run validate
npm.cmd test
```

## Linux

В обычном терминале Linux сначала из корня метарепозитория выполните `npm ci`,
затем перейдите в каталог стандарта. Проверки совпадают с macOS:

```sh
make bootstrap
npm run doctor
npm run validate
npm test
```

Обновление стандарта всегда формирует только отчёт или patch-файл для
последующего MR/PR. Локальные `CONTEXT.md`, словарь продукта и OpenSpec не
перезаписываются автоматически.

## Шаблон `templates/opencode.json`

В шаблоне вместо адреса модели стоит заглушка `https://<адрес из корпоративной инструкции>/v1`. Перед использованием
подставьте в `provider.corp-llm.options.baseURL` адрес из корпоративной инструкции (его выдаёт организатор курса) только в своей
рабочей копии конфигурации. Не коммитьте подставленный адрес: он не публикуется.

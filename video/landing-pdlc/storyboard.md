## Поправка 13:55 — одобрение в GitLab одно (слово владельца через 008 13:21)
Как показать понятно (сцена 4, 8 с):
```
 ┌ Merge Request · Спецификация кредитного калькулятора ────────────────┐
 │ 💬 [аналитик]  «Сценарий отрицательной суммы — уточнить правило»     │  0–3 с: комментарии появляются по очереди,
 │ 💬 [техлид]    «Реализуемо, лимит вынести в настройки»  ✓ решено     │  у каждого чип роли и одна строка; «✓ решено»
 │                                                                      │  загорается после ответа автора
 │ [ ✔ Одобрить ]  владелец продукта                                    │  3–6 с: кнопка одна, загорается последней,
 │ ──────────────────────────────── Принято · версия 2 ────────────────  │  6–8 с: строка «Принято · версия N»
 └──────────────────────────────────────────────────────────────────────┘
```
- Закадровый текст сцены 4: «Аналитик и техлид проверяют комментариями, владелец продукта одобряет — одно одобрение, и версия принята».
- Правило чтения: комментарий = чип роли + 💬 + одна строка; одобрение = единственная кнопка ✔ с чипом роли под нитью. Никаких «трёх галочек».
- Кто какой: владелец продукта — одобряет («это то, что я просил»); аналитик — смысл и полнота; техлид — реализуемость; архитектор — комментарий только при споре или изменении данных/интеграций (как на странице команды развития, матрица «решает»). Автор черновика отвечает в нити, «✓ решено» — закрытая нить GitLab.
- То же правило — для роликов курса r2 (t5/t6 «Отметки людей») и текста шагов: формулировка «три отметки» заменяется на «комментарии ревьюеров и одно одобрение». Это отдельный хвост 558/014, не ролик главной.

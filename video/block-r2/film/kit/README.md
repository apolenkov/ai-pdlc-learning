# Набор «Студия»: как собрать сцену N

Тёмный холст, Inter и JetBrains Mono (локально), коралловый и зелёный акценты. Всё оформление в `kit/tokens.css`;
смена стиля = правка этого файла. Сцены и компоненты менять не нужно.

```
film/
  scenes.json                манифест: n, duration, chapter, step, title, audio, audioDuration
  index.html                 корень. ГЕНЕРИРУЕТСЯ: node tools/build-index.mjs (руками не править)
  compositions/scene-NN.html ваша сцена (единственный файл, который вы пишете)
  assets/vo/scene-N.mp3, scene-N.alignment.json   озвучка и посимвольные тайминги (выдаёт координатор)
  assets/vo/scene-NN.alignment.js                 их JS-версия: node tools/json2js.mjs align <json> NN
  assets/rec/                картинка-заглушка или запись экрана, clicks-NN.js
  kit/tokens.css, components.css, kit.js
  tools/                     build-index, scene (check/snapshot/render одной сцены), json2js, test-kit
```

Правила: пишете только `compositions/scene-NN.html` и свою строку в `scenes.json`. Корневой `index.html` не трогаете.
Время в сцене всегда локальное (0 = начало сцены). Все моменты внутри фразы ставьте через `S.t("фраза", n)`,
числа вида `12.4` в тайминги не пишите (исключение: интервалы вроде «+0.3 с» от найденного момента).
Весь текст в кадре не меньше 28 px (токены уже такие), контраст AA (проверяет `check`).
Код только моноширинным `var(--k-font-mono)` (`JetBrains Mono Local`). Не использовать `monospace`, `ui-monospace`, `Menlo` —
иначе сборщик подтянет JetBrains Mono из сети.


## Подготовка block-0

В `scenes.json` сохранён массив из 20 записей: t0, t1, 01, …, t9, 09, 10.
У каждой записи `header: { "mode": "parts", "total": 9 }`. `build-index` передаёт
данные в `Kit.header` через `window.KIT_SCENES`; название части — `title`/`chapter`.
Явный вызов: `Kit.header(S, { header: { mode: "parts", total: 9 }, step: 2,
chapter: "Уточняем запрос", duration: 38 })`. Без `header` сохранён режим 14 шагов.

Сцены 01–09 помечены `planned: true`: их HTML пока отсутствует, `audio: null`.
Индекс резервирует заданные 362 с без подключения отсутствующих композиций;
с заставками шкала составляет 412 с. Это подготовительный индекс, не готовый фильм.
После создания сцены уберите `planned`, добавьте озвучку и alignment, уточните
длительность с паузами. Явный `--only` для отсутствующей сцены завершается ошибкой.

`node tools/build-titles.mjs && node tools/build-index.mjs` создаёт 11 заставок
(6 с + 9 × 4 с + 8 с) и индекс. Конец — `compositions/scene-10.html`.
Название команды и титул берутся из `docs/pages/sdlc-development/course-names.json`;
длительности заставок — константы в начале `tools/build-titles.mjs`, совпадение
со `scenes.json` проверяется. `build-captions.mjs` создаёт `renders/block-0.*`;
до озвучки SRT пуст, главы содержат плановые времена.

Проверки: `node --test tools/test-*.mjs`, `node tools/scene.mjs t1 check`
и `node tools/scene.mjs 10 check`. Медиа, рендеры и snapshots в Git не входят.
SVG в `assets/sketches/` сохранены как исходники скопированного sketch-kit.
Рецепты записи и рендера ниже — для следующего этапа; сейчас они не выполнялись.

## 1. Запуск за три шага

1. Добавьте объект в `scenes.json`, например `{ "n": 2, "duration": 40, "chapter": "Уточняем запрос", "header": { "mode": "parts", "total": 9 }, "step": 2, "title": "…", "audio": "assets/vo/scene-2.mp3", "audioDuration": 36.1 }`.
2. `node tools/json2js.mjs align assets/vo/scene-2.alignment.json 02` (создаёт `assets/vo/scene-02.alignment.js`).
3. Напишите `compositions/scene-02.html` по шаблону ниже. Проверка:

```bash
node tools/test-kit.mjs                              # самопроверка timeOf и деления субтитров
node tools/scene.mjs 2 check                         # lint + layout + контраст, должно быть 0 ошибок
node tools/scene.mjs 2 snapshot --at 2,6,12,18,24    # → film/snapshots/scene-02/*.png, смотрите каждый кадр целиком
node tools/scene.mjs 2 render                        # → film/renders/scene-02.mp4
node tools/build-index.mjs && npx --yes hyperframes@0.8.145 check   # общий фильм (его делает координатор)
```

`tools/scene.mjs` создаёт `film/work/scene-NN/` (копии assets, kit, compositions и свой index.html только с этой сценой); `work/` и `snapshots/` в Git не идут.
Для `HYPERFRAMES_NO_TELEMETRY=1 HYPERFRAMES_SKIP_SKILLS=1` скрипт ставит переменные сам.

## 2. Шаблон сцены

```html
<template id="scene-02-template">
  <div data-composition-id="scene-02" data-width="1920" data-height="1080" data-duration="40">
    <style>
      /* только локальные стили, с префиксом [data-composition-id="scene-02"] */
    </style>
    <script>
      (function () {
        const S = Kit.scene("02");            // S.tl — таймлайн, S.t/S.end — время по озвучке, S.root — корень
        const t = S.t;

        Kit.header(S, { chapter: "Уточняем запрос", step: 2, header: { mode: "parts", total: 9 }, duration: 40,
          parts: [{ n: 1, name: "Идея", at: 0 }, { n: 2, name: "Как сделать", at: t("Чтобы") + 0.1 }, { n: 3, name: "Получилось, если…", at: 34.5 }] });

        const s1 = S.stage(); gsap.set(s1, { autoAlpha: 1 });   // первый план виден сразу
        const s2 = S.stage();                                   // остальные планы скрыты до stageIn
        /* ...компоненты внутри планов (parent: s1)... */

        Kit.stageOut(S, s1, 10.0); Kit.stageIn(S, s2, 10.5);    // переход: сначала уходит старый, потом входит новый
        Kit.subtitles(S, {});
        S.finish(40);                                           // длительность сцены; регистрирует таймлайн
      })();
    </script>
  </div>
</template>
```

Обязательно: `Kit.header`, `Kit.subtitles`, `S.finish(duration)` последним. Планы — это `S.stage()` (абсолютный слой 1920×1080,
скрыт). Планы одной части не должны пересекаться по времени: `stageOut` длится 0,55 с, следующий `stageIn` ставьте через `+0.5`
(так нет наезда: `Kit.swap(S, outEl, inEl, t)` делает то же и возвращает момент входа).
Сцены 01–09 ещё предстоит написать; шаблон выше показывает их контракт.

## 3. Время по озвучке: `timeOf`

```js
S.t("Откройте")        // начало первого вхождения фразы (сек, локальные)
S.t("нажмите", 2)      // начало второго вхождения
S.end("Cmd+K")         // конец фразы
S.speechEnd            // конец всей речи
Kit.timeOf(S.align, "фраза", n)   // то же без S
```

Поиск по символам озвученного текста (регистр и ё/е не различаются при запасном поиске). Фраза не найдена — ошибка при сборке
(это намеренно: сцена не рендерится с неверным таймингом). Для ровных паузы в тексте используйте то, что реально произнесено.
Типичная раскладка: `ed.type(…, t("создайте файл"), S.end("intent.md"))`, `kc.press("win", t("Ctrl+K"))`.

## 4. Компоненты

Все функции принимают `S` и объект параметров, `parent` — элемент или селектор (по умолчанию корень сцены), `x, y, w, h` — пиксели
кадра 1920×1080. Компоненты скрыты до `show(at)`/своего времени. Возвращают объект с методами; методы ставят твины в `S.tl`.

### 4.1 Шапка: `Kit.header(S, { chapter, step, total=14, duration, parts, progress=[0,1], mode, enter })`
При `header: { mode: "parts", total: 9 }` слева «Часть N ·» и название текущей части, справа один ряд
из 9 чипов. Следующее описание относится к режиму по умолчанию.

Слева «Шаг N · осталось M» (`.k-step`; на шаге 14 — «последний шаг»), справа два блока по 7 сегментов (`.k-prog`): «На компьютере · шаги 1–7» и
«В GitLab · действия 8–14» с подписями над ними. Сегмент 62×46 px, номер 24 px. Пройденные залиты акцентом (тёмный номер), текущий — контур
со свечением, светлый номер и полоска прогресса шага (заполняется от `progress[0]` до `progress[1]` за `duration`; шаг на нескольких
сценах — `progress: [0.5, 1]`), оставшиеся приглушены. Блок текущего шага подписан ярче. Токены `--k-seg-*` (контраст AA проверен).
- `step: N` — обычная сцена шага. Заставка шага: `enter: true, progress: [0, 0]` — мягкий переход (0,15–0,75 с) из состояния предыдущей сцены: прошлый сегмент
  остывает в «пройден», новый зажигается, текст шага сменяется. Сцена шага N продолжает заставку без перехода.
- `step: null, mode: "intro"` — вступление: все сегменты приглушены, «14 шагов в двух частях» (сцена 0; с `enter: true` шапка плавно появляется — заставка T0).
- `step: null, mode: "done"` (по умолчанию для `step: null`) — итог: все залиты, «Готово» (сцены 15, 16; с `enter: true` последний сегмент заливается — заставка T15).
- Бейдж части (`.k-part`, под шапкой): `parts:[{n, name, at}]` — «Часть n · name» меняется маской вверх/вниз. `chapter` сохранён для совместимости (блоки считаются по номеру шага).
Единый вызов во всех сценах: `Kit.header(S, { chapter, step, total: 14, duration, parts })`. Шапка занимает y 20–106, бейдж 128–188; контент не выше y 200.

### 4.2 Субтитры: `Kit.subtitles(S, { maxChars=62, hold=0.35 })`
Берёт текст и тайминги из alignment. Предложение — до `.`, `!`, `?`, `…`. Длиннее `maxChars` — делится по запятой/двоеточию/тире
(так, чтобы половины были ближе по длине; без знаков — по пробелу). Реплика появляется на первом символе, исчезает перед следующей
или через `hold` после последнего символа. Не больше двух строк (CSS-клемп). Список в `S.cues`. Стиль: `.k-sub`, `.k-sub-pill`.

**block-0:** вшитые субтитры стоят выше зоны нативной панели плеера: `.k-sub { bottom: 130px }` (≥12 % высоты кадра, у block-0a было 44 px). Весь остальной
контент сцены должен оканчиваться выше ~y 865 (нижняя граница плашки субтитров ≈ 955, запас на два ряда текста).

### 4.3 Окно редактора: `Kit.editor(S, o)`
```js
const ed = Kit.editor(S, { parent: s2, x: 96, y: 250, w: 1240, h: 640, crumb: "учебная папка / без-git", visible: true,
  tabs: [{ name: "intent.md", active: true }],
  lines: ["# Заголовок", "", "- пункт", { t: "- добавленная строка", add: true }] });
```
Классы: `.k-ed .k-ed-bar .k-ed-tabs .k-ed-tab .k-ed-code .k-ln .k-no .k-tx .k-c .k-k (каретка) .k-hl .k-ov`.
Подсветка Markdown автоматическая (`.t-mark .t-head .t-dash .t-quote .t-bold .t-code .t-link .t-url .t-fence`; цвета в токенах `--k-code-*`).
Без `visible:true` окно скрыто до `ed.show(at)`. Строка — `string` или `{t, add:true}` (добавится позже).
Методы (всё возвращает `ed`, можно цепочкой):
- `ed.show(at)`, `ed.hide(at)`, `ed.move(at,{x,y,dur})` (сдвиг окна).
- `ed.type(from, to, t0, t1)` — печать строк from..to с кареткой. `t1` не задан — по `--k-type-dur-per-char`. Для разбега по речи: `ed.type(0,10,t("VS Code"),S.end("intent.md"))`.
- `ed.reveal(from, to, at)` — показать строки мгновенно (уже напечатано раньше).
- `ed.caretOff(at)` — погасить мигающую каретку (иначе мигает до конца сцены).
- `ed.mark(i, at, {tone:"accent"|"ok", off})` — подсветка строки полосой слева (`off` — когда погасить).
- `ed.morph(i, at)` — морфинг строки Markdown в оформленный вид (заголовок, пункт, цитата, абзац; ссылка → синий текст). Только для строк в одну визуальную строку. `ed.unmorph(i, at)` — обратно.
- `ed.addLine(i, at, {dur=0.9, type=true, off})` — раскрыть добавленную строку `lines[i]` (`add:true`), напечатать и подсветить зелёным как diff (`+` в поле). `ed.diffOff(i, at)` — убрать подсветку. Подходит для шагов 4, 6, 9, 12.
- `ed.dirty(at, on)` — точка «не сохранено» во вкладке, `ed.saved(at)` — точка становится зелёной.
Высота добавленной строки считается по ширине JetBrains Mono (0,6 em); если строка длиннее ширины окна, она переносится по словам.

### 4.4 Карточка тактов: `Kit.keycard(S, o)`
Вертикально: «Нажмите вместе» (клавиши) → «Отпустите обе клавиши» → «Нажмите» (клавиша). Варианты по ОС, тексты меняются через `labels`.
```js
// цепочка: Ctrl+K, отпустить, V
const kc = Kit.keycard(S, { parent: s5, x: 1240, y: 290, w: 584, variants: [
  { id: "win", label: "Windows и Linux", press: ["Ctrl", "K"], next: ["V"] },
  { id: "mac", label: "macOS",           press: ["Cmd", "K"],  next: ["V"] } ] });
kc.show(t("рядом"), "win");
kc.press("win", t("Ctrl+K"));            // клавиши вдавлены (коралл), держатся
kc.release("win", t("отпустите"));       // отпустили; появляется стрелка и карточка «Отпустите обе клавиши»
kc.then("win", t("нажмите", 2), 0.7);    // стрелка и карточка «Нажмите», клавиша V нажимается на 0,7 с
kc.switchTo("mac", t("На Mac") - 0.2);   // плавная смена варианта в том же месте
kc.press("mac", t("Cmd+K")); kc.release("mac", S.end("Cmd+K") - 0.2); kc.then("mac", t("затем") + 0.3);
kc.hide(t("Слева") - 0.25);

// одиночное сочетание (Ctrl+S): без `next` — карточки варианта друг под другом
const ks = Kit.keycard(S, { parent: s2, x: Kit.layout.rightX, y: 270, w: Kit.layout.rightW, variants: [
  { id: "win", label: "Windows и Linux", press: ["Ctrl", "S"] },
  { id: "mac", label: "macOS", press: ["Cmd", "S"] } ] });
ks.show(t("сохраните")); ks.press("win", t("Ctrl+S"), 0.6); ks.press("mac", t("Cmd+S"), 0.6);
```
Один вариант (клавиша одинакова везде, например Ctrl+`): `variants: [{ id: "all", label: "Windows, Linux и macOS", press: ["Ctrl", "`"] }]`, `kc.show(t)`, `kc.press("all", t)`.
Классы: `.k-kc .k-kc-flow .k-kc-stack .k-pill .k-kcard .k-keys .k-cap .k-plus .k-down`. В правой колонке (520 px) помещается цепочка целиком
(высота около 560 px); `layout:"flow"|"stack"` можно задать явно.

### 4.5 Кадр записи экрана: `Kit.screen(S, o)`
Ключ камеры принимает `protect: [{ x, y, w, h }]` в координатах исходной записи.
`Kit.screen` и `scr.camera()` синхронно бросают `Error`, если итоговый кадр режет
хотя бы один защищённый прямоугольник. Проверка учитывает масштаб, ограничение
центра границами записи и реальную высоту окна (она может быть меньше `1080 / scale`).
Проверяются все объявленные ключи, в том числе начальный: это строже порога
удержания 0,5 с. Промежуточные кадры движения проверяйте снимками.

Раскладки (`Kit.layout`): **left** (по умолчанию) — окно 1180 px слева (x 96, y 240, высота окна не больше 705 px), справа колонка
подсказок и карточек клавиш `Kit.layout.rightX` = 1304, `Kit.layout.rightW` = 520. **wide** (`layout:"wide"`) — общий план без колонки:
окно 1500 px по центру (x 210, y 200, высота до 740 px, лишнее по высоте обрезается камерой), подсказки кладут поверх окна снизу.
`x`, `y`, `w`, `h` можно задать явно (тогда раскладка не используется).
```js
const R = Kit.layout;
const scr = Kit.screen(S, { parent: s5, natural: { w: 1920, h: 1080 },            // размер записи в пикселях
  video: { el: "#rec-open", poster: "assets/rec/scene-02-open.first.png",         // см. «Запись mp4» ниже
           start: 22.4, duration: 9.0,
           clicks: [{ t: 1.66, x: 307, y: 95, label: "New File" }] },             // t — время ЗАПИСИ, kit сдвигает на start
  camera: [{ t: 21.3, cx: 330, cy: 170, scale: 2.2, dur: 1.0 }, { t: 30.1, cx: 960, cy: 540, scale: 1, dur: 1.2 }] });
//  или картинка:  src: "assets/rec/step.png", from: { x: 840, y: 520 }, clicks: [{ t: t("текстом,"), x: 1393, y: 52, label: "…" }]
scr.show(at);
scr.areas([{ text: "исходный текст", x0: 420, x1: 1170, tone: "accent", at: t("исходный") },      // x0/x1 в пикселях записи
           { text: "так прочитает человек", x0: 1170, x1: 1920, tone: "ok", at: t("справа"), align: "right" }]);
scr.camera(at, { cx, cy, scale }, dur, ease);                  // ещё одно ключевое положение камеры
```
Камера: `(cx, cy)` — центр в пикселях записи, `scale` — относительно «весь кадр по ширине окна» (1 = целиком, 2 = вдвое ближе). Кадр всегда
закрывает окно (края не показываются). Лёгкий параллакс: окно и тень слегка смещаются при зуме.
Курсор (`.k-cg`: кольцо `.k-ring`, пульсы `.k-pulse`, стрелка) движется между кликами за ≤1 с и пульсирует в момент клика; без кликов курсора нет.
После последнего клика гаснет через `cursorHold` (1,2 с; `0` — не гасить). `label` клика показывается 1,6 с над левым краем окна
(`.k-clk`, зона над окном общая с `areas`). Файл кликов записи: `[{"t","x","y","label"}]` (пиксели записи, `t` от начала записи); массив можно
вставить в сцену как есть.

**Запись mp4 (проверено рендером).**
1. `<video>` обязан быть в СТАТИЧЕСКОЙ разметке сцены (сборщик ищет видео до запуска скриптов; созданное из JS не подставится):
   ```html
   <video id="rec-open" class="clip" src="assets/rec/scene-02-open.mp4" muted playsinline data-start="22.40" data-duration="9"></video>
   ```
   `data-start` — число: момент сцены, когда запись начинается (считайте от озвучки: `время_фразы − момент_в_записи`, например клик на 1,66 с
   записи должен попасть на фразу «создайте файл» → `data-start = timeOf − 1.66`). `data-duration` — сколько показывать запись, не меньше длины файла.
   `Kit.screen` сверяет оба числа с `video.start`/`video.duration` и бросает ошибку при расхождении. Звука нет (`muted`).
2. Запись короче `data-duration`: после конца держится последний кадр (рендер повторяет его). До `data-start` видео скрыто: чтобы окно не было белым,
   дайте `poster` — первый кадр записи: `ffmpeg -i x.mp4 -frames:v 1 x.first.png`. Это фон слоя; `<img>` рядом с видео в слое не ставьте
   (ломает подстановку кадров при рендере).
3. Рендер: `node tools/scene.mjs N render` сам добавляет `--video-frame-format png` (текст интерфейса без JPEG-шума).
4. Записи 1920×1080 при ширине окна 1180 мелкие: показывайте крупно камерой (`scale` 1,7–2,2) на то место, о котором речь.
Синхронизация проверена на сцене 1 (запись «создать файл»: клик New File, вставка, сохранение совпали с фразами диктора).

**Рецепт block-0a: запись из нескольких кусков и подгонка к речи.** Скрипты `retime-*` не скопированы; пути ниже относятся к исходному проекту. `Kit.screen` не режет и не замораживает запись: у `video` нет `mediaStart`
и «держать кадр». Нужная раскладка нажатий делается производным mp4, одним `<video>` на запись:
1. В `assets/rec/retime-scenes-05-14.py` для записи задайте якоря «время записи → время сцены» (`(t_записи, t_сцены)`; время сцены берите из озвучки: `node` + alignment
   или `S.t("фраза")`) и границы `rec_start`/`rec_end`. Между якорями скрипт сам держит последний кадр (`hold`), замедляет кусок (режим `"slow"`, ввод текста) или вырезает середину.
   Ускорения нет: быстрее 1× запись не идёт. Якорь на ввод текста ставьте на кадр ДО появления текста.
2. `python3 assets/rec/retime-scenes-05-14.py <имя>` печатает `data-start`, длительность и клики во времени ПРОИЗВОДНОЙ записи; создаёт `<имя>.retimed.mp4` и `<имя>.retimed.first.png` (poster).
3. В разметке сцены `<video id class="clip" src="…retimed.mp4" muted playsinline data-start="…" data-duration="…">` (`data-duration` не меньше длины файла, до конца плана с записью).
   В скрипте: `video: { el, start, duration, poster, clicks }` с теми же числами; `clicks[].t` — время производной записи (kit сам прибавляет `start`). Подпись (`label`) ставьте только у ключевых кликов, иначе они накладываются.
Вторая запись в той же сцене (сцены 6, 8, 9, 12) — второй `<video>` и второй `Kit.screen` в своём плане.

### 4.6 Карточки «Получилось, если…»: `Kit.goals(S, o)`
```js
Kit.goals(S, { parent: s6, summary: "Один файл — два вида: исходник и предпросмотр", items: [
  { icon: "file", text: "один файл" }, { icon: "views", text: "два вида" }, { icon: "same", text: "текст одинаковый" }] });
```
2–4 пункта; иконки `Kit.icons`: `file views same check folder save key branch commit merge cloud` (или своя строка SVG, `currentColor`).
Блок по умолчанию стоит по центру свободной зоны по вертикали (`x`=96, `w`=1728 по умолчанию; `y` игнорируется, `center:false` + `y` — поставить вручную).
Карточка 260 px высотой, иконка 72 px, текст 46 px (токены `--k-goal-h`, `--k-goal-ic`, `--k-fs-goal`). `summary` — строка-итог шага под карточками
(42 px, одна строка, до ~55 знаков), появляется следом за последней карточкой.
Старт по умолчанию — `S.speechEnd`; расписание считает компонент так, чтобы последняя карточка вышла не позднее конца речи + 1,5 с;
иначе бросает ошибку (тогда задайте `start` раньше). Классы `.k-goals .row .k-goal .k-goal-sum`.

### 4.7 Боковая подсказка: `Kit.aside(S, o)`
Карточка в правой половине, чтобы общие планы не пустовали.
```js
const a = Kit.aside(S, { parent: s2, x: Kit.layout.rightX, y: 250, w: Kit.layout.rightW, title: "Страница курса", text: "Пример intent.md", button: "Копировать" });
a.show(t("Вставьте")); a.hide(t("сохраните") - 0.1);
Kit.aside(S, { parent: s2, x: Kit.layout.rightX, y: 330, w: Kit.layout.rightW, tail: false, html: "<div class='…'>любая разметка</div>" });
```
`tail:true` рисует стрелку влево (на главный объект); `html` — произвольное содержимое. Классы `.k-aside .ttl .sub .btn .mono .cmp`.
Правило: на каждом общем плане и справа, и слева что-то есть. Левая колонка x 96…1276 (окно записи/редактора), правая колонка x 1304…1824 (`Kit.layout.rightX`/`rightW`).

### 4.9 Схема Git: `Kit.gitGraph(S, o)`
```js
const g = Kit.gitGraph(S, { parent: s3, x: 96, y: 250, w: 1500, h: 560,
  lanes: [{ id: "remote", label: "Сервер", color: "var(--k-git-remote)", y: 80 },
          { id: "main", label: "main", color: "var(--k-git-main)", y: 280 },
          { id: "feat", label: "ветка", color: "var(--k-git-feature)", y: 480 }],
  commits: [{ id: "c1", lane: "main", col: 0, label: "Commit", at: t("коммит") },
            { id: "c2", lane: "feat", col: 1, at: t("ветку") }, { id: "c3", lane: "main", col: 3, at: t("слияние") }],
  edges: [{ from: "c1", to: "c2", at: t("ветку"), color: "var(--k-git-feature)" }, { from: "c2", to: "c3", at: t("слияние") }],
  arrows: [{ from: { id: "c3" }, to: { lane: "remote", col: 3 }, label: "Push", at: t("отправьте") }],
  badges: [{ on: "c3", text: "MR !1", at: t("запрос") }] });
```
Точки коммитов (`commits`) всплывают, рёбра (`edges`) рисуются линией (ветка/слияние — кривой), стрелки (`arrows`) с подписью (Commit,
Push, Pull, Merge) идут между точками или дорожками (`{lane, col}`), значок `badges` (MR !1) справа-сверху от коммита. `labelW` — ширина
подписей дорожек (по умолчанию считается по самой длинной подписи), `colW` (150) — шаг колонок. Подписи 28 px. Проверен на демо (3 дорожки, ветка, слияние, Push/Pull, значок): кадр читается; `col` может быть дробным. Дорожки не должны
наезжать на подписи: ставьте `y` с шагом не меньше 200.

### 4.10 Кинетическая типографика и переходы
- `Kit.kinetic(S, { parent, x, y, size=140, text, at, stagger, color })` — слова въезжают из масок по одному; `.out(t)` — уезжают вверх.
- `Kit.stageIn(S, el, t)`, `Kit.stageOut(S, el, t)` — переход между планами/частями: blur 14 px и масштаб 0,95 ↔ 1,05 (токены `--k-blur`, `--k-scale-in/out`).
- `Kit.swap(S, outEl, inEl, t)` — оба сразу; `Kit.popIn/popOut(S, el, t, d)` — появление/уход карточки.

## 5. Токены (`kit/tokens.css`)
Цвета: `--k-bg --k-text --k-text-2 --k-accent --k-accent-soft --k-ok --k-info --k-panel --k-line --k-win --k-key-*`, код `--k-code-*`, Git `--k-git-*`.
Шрифты: `--k-font-sans`, `--k-font-mono`. Размеры: `--k-fs-*`, `--k-lh-code`, `--k-key-h`. Радиусы `--k-r-*`, тени `--k-shadow-*`.
Длительности `--k-dur-*`, easing `--k-ease-*` (имена GSAP), переход `--k-blur`, `--k-scale-*`. JS читает их при сборке сцены.

## 6. Ловушки
- Не используйте `Math.random`, `Date.now`, `fetch`; анимация только через `S.tl` (GSAP, paused).
- Фильтр `blur` и `autoAlpha` ставят компоненты; свои твины по тем же элементам не ставьте.
- Каждый элемент одного плана скрыт до своего `show`; не забывайте `S.stage()`+`stageIn`.
- Два плана на одной стороне экрана не должны быть видимы одновременно (проверка layout даёт `content_overlap`): гасите прежнюю подсказку (`hide`) до появления новой.
- Ограничение сборщика: `<link>` и `<script>` подключает только корень (его генерирует `tools/build-index.mjs`); в сцене своих `<script src>` нет.

В режиме `header.mode: "parts"` название главы находится слева под «Часть N ·», отдельно от чипов.
В старом ролике `block-map` сохранена прежняя шапка со знаменателем.

Подпись состояния под шапкой (`parts[].name`) не должна пересказывать шапку: такую подпись не переименовывают, а убирают (`{ n, blank: true, at }` оставляет паузу между темами без текста).

# kit.js: общий источник и сборка копий

`kit.js` — набор компонентов «Студия» для HyperFrames: ~48 КБ, 812 строк, около 17 разделов
(токены, DOM, иконки, время по alignment, сцена, шапка, субтитры, Markdown, редактор, карточка
клавиш, кадр записи экрана, итоговые карточки, подсказка, плитки пути, схема Git).
Раньше файл жил копией в каждом `video/<ролик>/film/kit/kit.js` (30 копий), генератора не существовало,
копии разошлись. Инвентарь 30 копий, расхождения и причины — `kit/targets/INVENTORY.md`.

## Структура

```
video/_shared/
  build-kit.mjs             сборка и проверка порождаемых копий
  build-kit.d.mts           типы для scripts/video-shared.test.ts
  KIT.md                    это описание
  kit/
    parts/01-core.js        токены, DOM, иконки, время по alignment, сцена, общие движения
    parts/02-text.js        шапка, субтитры, Markdown
    parts/03-editor.js      окно редактора, карточка тактов клавиш
    parts/04-screen.js      кадр записи экрана
    parts/05-stage.js       итоговые карточки, подсказка, плитки пути, схема Git, окно Kit
    variants/<X>.json       варианты роликов B/C/D/E/F/G: построчные патчи над эталоном
    targets/lane-N.txt      списки полос (четыре-пять роликов), источник списка порождаемых копий
    targets/INVENTORY.md    снимок 30 опубликованных копий: sha, вариант, причина расхождения
    targets/<ролик>.json    конфиг ролика: { "variant": "B", "bodySha256": "…" }
    README.md, tokens.css, components.css, people.js, sketch.js, sketch.css — по-прежнему
                            копируются в ролики скриптом video/_shared/sync.mjs
```

Части — фрагменты одного замыкания `(function () { … })();`: каждая часть не самостоятельный модуль,
а кусок исходного файла. Порядок задан списком `PARTS` в `build-kit.mjs`; сборка — конкатенация.
Каждая часть ≤ 12 056 Б (лимит пакета — 20 000 Б на файл).

## Команды

```sh
node video/_shared/build-kit.mjs           # записать порождаемые копии kit.js
node video/_shared/build-kit.mjs --check   # сверить копии с частями и sha роликов; код 1 при расхождении
node video/_shared/sync.mjs --check        # сверить остальные общие файлы роликов
```

`scripts/video-shared.test.ts` (входит в `npm test`) проверяет синхронность, сборку порождаемых копий
и целостность списков полос: сироты конфигов, дубли роликов и копии с баннером вне списков — расхождение.

## Эталон и варианты роликов

Рефакторинг не меняет вид роликов: общий источник должен воспроизводить **каждую** опубликованную
копию, а не сводить копии к одному виду.

- `REFERENCE_SHA256` в `build-kit.mjs` — sha256 тела сборки без баннера, **вариант A**: эталонная
  копия kit.js на 19.10.2026 (13 из 30 копий). Части и эту константу менять нельзя: иначе
  сломается воспроизведение опубликованных роликов.
- Вариант ролика (`B`, `C`, `D`, `E`, `F`, `G`) — `kit/variants/<X>.json`:
  `{ "variant": "X", "description": "…", "bodySha256": "…", "hunks": [...] }`; `hunks` — построчные
  замены в теле эталона `{ "start": <строка 1-based>, "remove": [...], "add": [...] }`. Данные
  выведены из фактических опубликованных копий (дифф к эталону, см. `targets/INVENTORY.md`); `bodySha256`
  — sha256 тела опубликованной копии без баннера.
- Конфиг ролика — `kit/targets/<ролик>.json`: `{ "variant": "B", "bodySha256": "…" }`. `bodySha256`
  — полное значение поля `bodySha256` из `kit/variants/<X>.json` (для A — `REFERENCE_SHA256`), поле
  обязательно; брать sha из `targets/INVENTORY.md` нельзя — там у пяти landing-* примечание ¹ путает sha
  файла с баннером и sha тела. Без конфига ролик порождается эталоном (вариант A), ожидаемая sha —
  `REFERENCE_SHA256`.
- Критерий перевода копии на порождаемую: тело сгенерированного `film/kit/kit.js` (без баннера)
  побайтно равно текущей опубликованной копии, то есть sha256 совпадает с sha ролика в конфиге.
  Сборка сверяет per-video sha и не пишет копии, если эталон или вариант разошлись.
- Порождаемые файлы помечены `linguist-generated=true` в `film/kit/.gitattributes` (создаёт
  генератор). Ручные копии метки не получают.

Политика расхождений: локальная правка, которую нельзя выразить вариантом источника (H, `block-0a`
со своим `split` шапки и тест-фикстурами), остаётся ручной копией и в списки полос не входит.
Правка вида ролика в рамках рефакторинга не делается: висящие точки, редакторские правки подписей
и т. п. — отдельная задача при рендере.

## Проверка кадров до/после

Перевод копии на порождаемую не должен менять вывод: снимаются ключевые кадры сцен (полный рендер
ролика не нужен).

```sh
cd video/<ролик>/film
env HYPERFRAMES_NO_TELEMETRY=1 HYPERFRAMES_SKIP_SKILLS=1 \
  npx --yes hyperframes@0.8.166 snapshot --at <t1,t2,...> --no-end -o <каталог> --describe false
```

Времена берутся из `scenes.json` (середина нужных сцен). «До» — опубликованная копия: `snapshot`
чистой копии ролика из базовой ветки (до замены `film/kit/kit.js` на порождённую). «После» — рабочая
копия после `node video/_shared/build-kit.mjs`. Кадры сравниваются побайтно (`md5` PNG): для варианта
с тем же телом diff = 0 (в файле отличается только строка баннера-комментария). Если diff ≠ 0 — копия
не переводится, причина и diff — в отчёт полосы. Рендер — тяжёлая проверка: не больше двух
одновременно на машину, остальные ждут в очереди.

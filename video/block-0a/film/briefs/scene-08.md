# Сцена 08 — Отправляем в GitLab (30.0 с, речь 28.0); текст: блок 08 в `../../storyboard.md`
Зритель должен понять: блоки 1–7 — учебная папка локально; в работе проект лежит в GitLab: Fork (своя копия на сервере) → Clone (на компьютер с историей) → своя ветка; Commit пишет версию у вас, а Sync Changes (Push) отправляет её в GitLab.
Смотреть первым: схема «компьютер | GitLab» (две колонки), по ней идут стрелки Fork, Clone, Push.
Было → стало: «учебная папка (только компьютер)» → «проект в GitLab (общий)».
Ритм: «Блоки с первого по седьмой — учебная папка» → колонка «компьютер»; «В работе проект уже лежит в GitLab» → колонка «GitLab»; «Сначала сделайте свою копию… Fork» → форма Fork project (Project URL, Visibility level — кадр живого GitLab, форму НЕ отправлять) + стрелка Fork; «Затем скопируйте её на компьютер… Clone» → запись scene-08-clone-button (меню Clone) + стрелка Clone, затем scene-08-remote (git remote -v) если успевает; «работайте в своей ветке»; «Отправка… Push; в VS Code её делает кнопка Sync Changes» → запись scene-12-fix (на ней кнопка Sync Changes с 1↑; scene-09-push показывает Publish Branch для новой ветки), стрелка Push; «Commit записывает версию у вас, Push отправляет её в GitLab — это два разных действия» → пара «Commit — у вас / Push — в GitLab».

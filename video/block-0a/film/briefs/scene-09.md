# Сцена 09 — Просим проверить: Merge Request (23.2 с, речь 21.2); текст: блок 09 в `../../storyboard.md`
Зритель должен понять: Merge Request — запрос проверить правки; выбираем куда вносим (Target) и проверяющего (Reviewer); проверяет коллега, принимает владелец решения; одобрение не объединяет — Merge отдельный шаг.
Смотреть первым: форма New merge request (Source limit-rows → Target main, поле Reviewer).
Ритм: «Откройте Merge Request» → запись scene-10-new-mr (форма в ней уже даёт «Reviewer» в единственном числе, GitLab 15.10 — перепроверено; пересъёмка не нужна); «Выберите, куда вносим изменения, и проверяющего» → подсветка Target и Reviewer; «Проверяет коллега — техлид или другой аналитик» → карточка «Проверяет: коллега»; «читает, оставляет замечание к строке и одобряет» → запись scene-11-comment (комментарий к строке); «Принимает изменение владелец решения» → карточка «Принимает: владелец решения»; «Одобрение ещё не объединяет ветки: объединение — отдельный шаг, Merge» → пара «одобрение ≠ Merge» + кнопка Merge из scene-13-merge.
Скетч/схема/карточка: записи scene-10, scene-11, scene-13; роли — две карточки `Kit.aside`.
Не делать: крупный план боковой колонки страницы MR (там сам GitLab пишет «0 Reviewers»); «Reviewers» во множественном (в GitLab 15.10 — «Reviewer»); создавать или отправлять MR на живом GitLab.
Проверка кадров: 2, 6, 10, 14, 18, 21 с.

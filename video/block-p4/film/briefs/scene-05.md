# Сцена 05 — Контракт и запросы изменения (макет, не производственный тайминг)

Вход исполнителя до правок: загрузить локальные HyperFrames router/core (для движения также animation/keyframes), прочитать course-video/SKILL.md, motion-rules.md и brand-spec.md. Перед независимым ревью пройти critique-loop: разведчик по кадрам выставляет 8 оценок, ≥14/16, ни одного 0; сохранить протокол. Чтение этого брифа навыки не заменяет.

Зритель должен понять: требования принимают до кода; архив возможен только после слияния всех MR кода и отдельного MR подтверждённых статусов задач; выпуск проверяют отдельно.
Смотреть первым: контракт связывает продукт и запрос с версиями; затем фокус последовательно идёт по трём этапам.
Было → стало: несвязанные сведения → контракт с SHA каждого репозитория → принятые требования → отдельные MR реализации и статусов → join → архив → доказательства выпуска по сервисам.

Ритм: восемь иллюстративных состояний. Контракт: продукт, запрос, ветки, приёмка; отдельно Store SHA / исходный web SHA / исходный api SHA. Пустое обязательное поле останавливает подготовку. Планирование — Store, требования до кода. Реализация — web и api с собственными MR, SHA и проверками. Следующее состояние добавляет отдельный Store MR принятого изменения и подтверждённых tasks.md, не переносит tasks.md в код. Join «Все MR кода и статусов слиты» открывает Store: архив. Выпуск web и api подтверждаем по отдельности; слияние не равно выпуску. Число запросов зависит от числа репозиториев: фиксированное «четыре» из другого ролика сюда не переносить.

Схема: не четыре тесные плитки в ряд, а последовательная смена двухколоночных состояний; два кодовых MR объединены скобкой с отдельным MR Store перед join. В контракте вместо выдуманных хешей — читаемые поля полного SHA, пометка «пример». Результаты макета иллюстративны, не receipt реального слияния или выпуска.

Не делать: один общий SHA для всех репозиториев; архив сразу после кода без статусов; зелёный статус до проверок; выдуманные VO-якоря. Внешний стиль существующей «Студии» неизменен: локальные токены и шрифты, ≥28 px, контент выше y=825, субтитры bottom=130 px. Пояснения входят по x, подтверждение — pop; один фокус за раз.

Тайминг: [макет](../mockups/scene-05/index.html) — самостоятельный проект, без аудио, alignment и производственных длительностей. Неподвижное чтение каждого состояния ≥ слов / 3 + 1 с после входа. После принятого alignment интегратор заменяет все отсутствующие старые фразы-якоря и проверяет реальные окна чтения. Заставку t5 и LEADS[5] меняет интегратор: «Планирование · код и статусы · архив» (RV685plan P2-2); этот макет их не переписывает.

Проверка кадров: все восемь midpoint в [списке снимков](../mockups/snapshot-times.json), плюс 0, 0.1, 0.3 и последний кадр. До разрешённого родителем LANE браузер не запускается. После снимков: critique-loop разведчиком ≥14/16, ни одного 0; протокол critique/scene-05.md — интегратору, затем независимое ревью. R1 макета после снимков — 16/16 независимым разведчиком, см. [протокол](../critique/scene-05.md); production PASS не заявлен. Синхронная правка гайда о tasks.md и join остаётся текстовому воркеру.

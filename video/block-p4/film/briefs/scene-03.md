# Сцена 03 — Store шаг за шагом (макет, не производственный тайминг)

Вход исполнителя до правок: загрузить локальные HyperFrames router/core (для движения также animation/keyframes), прочитать course-video/SKILL.md, motion-rules.md и brand-spec.md. Перед независимым ревью пройти critique-loop: разведчик по кадрам выставляет 8 оценок, ≥14/16, ни одного 0; сохранить протокол. Чтение этого брифа навыки не заменяет.

Зритель должен понять: Store подключают на каждой машине; локальное изменение становится общим только после отправки ветки и MR.
Смотреть первым: активный шаг из шести, затем одно действие в окне соответствующей машины.
Было → стало: локальная папка → общий Store → указатель из api → изменение на ревью. Doctor не означает принятия требований.

Ритм: шесть смысловых шагов «создать / отправить / подключить / связать / изменить / проверить», внутри — последовательные иллюстративные состояния. Машина 1: setup вне другого Git-репозитория; пустой GitLab-проект, remote, первый push. Машина 2: clone, отдельно register; mkdir → printf строки store: → init; new change; отдельная ветка Store → add → commit → push → MR; doctor; последнее предупреждение. Каждая команда из текущего гайда отдельной строкой после «В терминале:». Register — только терминальная команда, без выдуманной UI-пары. Конфигурацию и init в рабочей копии выполняет один человек; остальные получают файлы из Git.

Новый Git-фрагмент: сначала «В GitLab: Create Branch», затем switch; Stage Changes → add; Commit → commit; Publish Branch/Push → push. Подпись «В GitLab» сохранена по буквальному брифу. Независимое ревью Astra выявило конфликт: Stage Changes/Publish Branch относятся к локальному VS Code, а не GitLab. До производства координатор должен согласовать фактические «В VS Code / В терминале»; текущий макет НЕ инструкция по реальному интерфейсу, эту подпись не переносить молча в выпуск. Для MR отдельно «В GitLab: MR в main Store», «Команда Git не нужна». Требования принимают до кода. Исходные команды — [гайд](../../../../docs/pages/sdlc-development/guides/metarepository.md#L55-L151).

Схема: две подписанные машины, один терминал в фокусе, неизменная полоса шести шагов. Короткий вход пояснения по x, результат — scale/pop; выход короче входа. Стиль «Студия»: существующие tokens.css, локальные Inter / JetBrains Mono, один коралловый акцент, зелёный только для подтверждённых результатов. Контент y<825, шрифт ≥28 px, зона субтитров bottom=130 px.

Не делать: не переносить условные секунды в scenes.json; не подделывать alignment или S.t; не показывать весь список команд сразу; не называть doctor одобрением. Beta — одна фраза будущей речи без постоянной плашки; в макете её не дублируем. Только последнее состояние содержит «Синхронизации нет — перед работой забирайте изменения через git pull».

Тайминг: [изолированный макет](../mockups/scene-03/index.html) намеренно длиннее будущей речи. У каждого состояния неподвижное чтение ≥ слов / 3 + 1 с после входа. Это демонстрация состояний, НЕ доказательство, что полный Git-фрагмент помещается в новую VO. После принятого alignment интегратор привязывает новые фразы, удаляет старые якоря и проверяет предупреждение ≤5 с. Если команды не помещаются, заменить весь подробный Git-фрагмент компактным «Отдельная ветка Store → commit/push → MR» + «Команды — в гайде», без ускорения и уменьшения текста. Tail-t4 сохранить отдельно, ничего под ним не привязывать.

Проверка кадров: midpoint каждого состояния — [список снимков](../mockups/snapshot-times.json); также 0, 0.1, 0.3 и последний кадр. Browser/check/snapshot — только после координации LANE родителем. Затем critique-loop: разведчик оценивает 8 критериев, ≥14/16, ни одного 0; протокол ведёт интегратор в critique/scene-03.md до независимого ревью. R1 макета после снимков — 16/16 независимым разведчиком, см. [протокол](../critique/scene-03.md); production PASS не заявлен.

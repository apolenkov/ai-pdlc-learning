# Звук: только голос (TASK-671)

Правило TASK-671. У учебных роликов звук — только озвучка сцен: без фоновой музыки, эффектов и подложки. `sfx-mix --music`, `bed-loop` и `mix-v35` для курса не использовать. Манифест такого ролика несёт `"audio": "voice-only"`; строка «Музыка и звук» на странице показывается только у роликов без этого поля. Наличие поля у каждого манифеста сторожит `scripts/video-manifest-voice-only.test.ts`; ролик, ещё не пересобранный, стоит в `VOICE_ONLY_PENDING` (список только сокращается), исключение с причиной — в `VOICE_ONLY_EXCEPTIONS`.

Сборка — `video/_shared/tools/voice-only.ts`, один конфиг на ролик (`task671-rollout-config/v1`: `id`, `pin`, `video.timeBase`, `base.samples48`, `expectedDelta16`, `replicas`, `results.root`; относительные пути — от каталога конфига). Запуск из корня репозитория, вход и ffmpeg проверяются по SHA, результат пишется только в каталог результатов вне Git:

```sh
node --experimental-strip-types video/_shared/tools/voice-only.ts --from-pin <config.json> --plan-only
node --experimental-strip-types video/_shared/tools/voice-only.ts --from-pin <config.json>
```

- Режимы. `--from-pin` — ролик уже выпущен, вход — 720p-пин с готовым звуком, задержка реплики `data-start × 48000 + δ`, где δ — измеренный сдвиг пина: `expectedDelta16` × 3 из конфига (значения по умолчанию нет, без поля сборщик останавливается; у r3 80 → 240 отсчётов, 5 мс). `--from-render` — новый ролик, вход — голый рендер `renders/<фильм>.raw.mp4`, δ = 0. `--plan-only` — только проверка конфига и SHA входов, печать плана и аргументов; ffmpeg не запускается. Сначала всегда `--plan-only`.
- Что собирается. Голосовая шина заново из `assets/vo/scene-*.mp3` (тишина на всю основу, `adelay` в отсчётах 48 кГц, `amix normalize=0`; реплика длиннее `data-duration` обрезается), затем два прохода loudnorm: I −16, LRA 11, потолок фильтра TP −2,5; второй проход идёт с измеренными значениями первого (`linear=true`). Кодек — AAC-LC моно 48 кГц 128k, видео копией, `+faststart`.
- Окно приёмки (проверяет сам сборщик по готовому файлу — I и true peak повторным замером ebur128 после кодера — и дополнительно по `output_i`/`output_tp` loudnorm: те сняты до ограничителя и кодера): интегральная громкость I ∈ [−16,5; −15,5], true peak ≤ −1,5 dBTP. Иначе статус `BUILT_P6_FAIL`, кандидат не принимается; замеренные значения — в квитанции (`encodedIntegratedLufs`, `encodedTruePeakDb`).
- Кодер. По умолчанию `aac` и `--audio-bitrate 128k`; для block-i2 и block-i4 принят метод TASK-688: `--audio-bitrate 192k` меняет только `-b:a` второго прохода, без изменения фильтров, громкости, задержек и видеопотока. Остальные принятые файлы не пересобираются. Оба значения требуют того же окна P6 после AAC и точного равенства длины основе по P4. Если true peak готового файла выше −1,5, второй проход один раз пересобирается с `aac_at` при том же bitrate (отклонённый файл остаётся рядом как `*.aac-rejected.mp4`, причина — в квитанции: `encoder`, `fallbackReason`). Альтернатива — `--pre-encoder-ceiling-db X` (ограничитель после loudnorm, перед кодером); с ней кодер не меняется и пересборки нет, а громкость готового файла может уйти ниже окна. `aac_at` не гарантирует длину: ранее у block-i2/i4 он добавлял 640/960 отсчётов, а потолок −5 дБ давал I −17,05/−17,16 (doc-508); эти варианты по-прежнему отклонены.
- Проверки вне Git. Независимые инструменты `qc.mts`, `position-check.mts`, `asr-check.mts`, `clean-bus.mts` лежат не в репозитории: каталог раскатки TASK-671 вне Git (`audio671-binding/rollout/tools` в рабочих материалах CustomDev; путь — в doc-508; пороги — `thresholds.proposed.json` там же; сводки и отчёты — рядом, в Git не нести). Порядок: сборщик → `clean-bus.mts --config … --receipt <квитанция> --out-dir …` (шина без loudnorm и кодека) → `qc.mts --config … --candidate … --original … --bus … --out <новый каталог>` (формат, длина, громкость, паузы, склейки) → `position-check.mts run` для оригинала и кандидата, затем `compare` (позиции реплик и коэффициент не хуже оригинала с допуском 0,003) → `asr-check.mts run` для кандидата, оригинала и чистой шины, затем `compare` (слова: допуск max(1 п.п., 3 слова) к чистой шине; реплика пропала, если окно тише −40 dBFS). Если инструментов на машине нет, порядок выше воспроизвести нельзя: сообщить координатору, не писать замену по памяти.
- Решение при провале. Кандидат не прошёл хотя бы одну проверку — старый звук остаётся: манифест и Registry не трогаются, ролик записывается в исключения теста с причиной. Bitrate 192k не отменяет ни одной проверки. Пины ветки подготовки могут указывать на ещё не загруженные версии; это не публикация и не live readback. Registry и сайт обновляются только после отдельного разрешения и прослушивания.
- Чего эти проверки не доказывают. mp4 нет в Git, поэтому в CI звук не проверяется; PASS значит «числа проходят», не «звучит хорошо» — слух (начало, стыки реплик, конец) отдельным шагом до Registry.

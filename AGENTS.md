# AGENTS.md

Репозиторий — исходники курса «Анализ с ИИ-агентами». Читают его люди и ИИ-агенты, правки идут через pull request.

## Границы

- В репозиторий попадает только учебный материал: курс, гайды, примеры, медиа, стандарт аналитика.
- Не добавляйте: пароли, токены, ключи, персональные данные сотрудников, внутренние выгрузки и карты команд,
  корпоративные навыки, материалы закрытых проектов. Список границ — `docs/BOUNDARIES.md`.
- Имена людей в примерах только вымышленные. Реальные адреса и учётные данные в снимках экрана закрывайте.
- Лицензию не добавляйте и не меняйте: решение за владельцем.

## Структура и источники

- Исходники сайта: `docs/pages/sdlc-development/`. Тексты гайдов — `guides/guide-stages.ts`, отрисовка — `guides/guide-data.ts`.
- `dist/` — только результат сборки, не правится вручную и не коммитится. `guides/metarepository.html` не существует в исходниках:
  страница строится из двух файлов: `guides/metarepository.md` и `guides/metarepository/01-steps.md`.
- Карта курса на `guides/intent.html` тоже не в странице: между пустыми маркерами `<!-- course-map:start/end -->`
  сборка вставляет генерируемую часть `guides/intent/course-map.html` (пишет `scripts/course-map.ts --write`),
  чтобы страница оставалась ниже лимита agent-size-guard. Правьте страницу, часть не трогайте.
- Стили guides правятся в частях `guides/learning-enhancements/*.css`: `learning-enhancements.css` собирается
  из них и в дереве исходников его нет; новый файл-часть добавляйте в `scripts/learning-enhancements-css.ts`.
- Общая навигация задаётся в `scripts/site-navigation-contract.ts`. После изменения запустите
  `node --experimental-strip-types scripts/update-site-navigation.ts`.
- Маршруты сайта перечислены в `scripts/pages-route-manifest.ts`, ресурсы гайдов — в `scripts/guide-content.ts`.
  Новая страница или файл, которых нет в этих списках, не попадут в сайт: сборка и тесты это проверяют.

- Ролики: исходники в `video/block-*`, mp4 вне Git (GitHub Release `media-v1`, версии и sha256 — в `video-manifest.json`). Не коммитьте mp4 и рендеры;
  правила производства — `skills/course-video/SKILL.md`.

## Бэклог, спецификации и worktree

- Цель, состояние и план задачи ведёт личный Backlog (`~/work/backlog`, CLI `backlog`); требования и сценарии изменений — OpenSpec
  (`openspec/`). Связывайте карточку и change ссылками. Сгенерированные `openspec-*` навыки восстанавливаются командой
  `openspec init --tools codex,claude` и в Git не попадают.
- Рабочие копии держите внутри репозитория: `.worktrees/<ветка>` (каталог в `.gitignore`), не в `/tmp`.
  После слияния убирайте worktree и ветку; незавершённую работу не оставляйте без коммита.

## Команды

```sh
npm ci
npm run build:site
npm run preview
npm test
npm run typecheck
```

Перед завершением работы запустите `npm test` и `npm run typecheck`. Хуки Git (`lefthook`) не обходите.

## Правила изменений

- Сообщения коммитов — Conventional Commits; области: `course`, `guides`, `examples`, `standards`, `skills`, `site`, `scripts`, `docs`, `repo`, `ci`, `deps`.
- Зависимости и версии Node, npm, образов CI держите на последних стабильных, сверяя с реестром на дату правки.
- Скриншоты: пары `*.png` и `*-600.webp`/`*-1200.webp` меняйте вместе. Пустое место для скрытого снимка держит файл-заглушка.
- Один файл в одном pull request правит один автор; параллельные правки одного файла согласуйте в обсуждении.
- Видимый дефект на странице (обрезка, наложение, нечитаемый контраст) блокирует приёмку правки.
- Текст курса и стандарта пишите по [правилам оформления курса](docs/COURSE-RULES.md): интерфейс и терминал парами, без кодов шагов, без слова «отметки», термины латиницей, команда — «Команда развития процессов AI PDLC»; `npm test` проверяет это на всех страницах курса и ловит нарушения.
- Каждую правку сайта проверяйте на 1440, 1024 и 390 px; смотрите кадр целиком.
  Видимый дефект на 390 px блокирует PASS. Мобильное меню и полоса маршрута
  входят в объём работ (TASK-562) и не исключаются из проверки.
